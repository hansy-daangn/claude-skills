# 유저 캠페인 소재별 성과 표 추출 (CSV)

두 개의 "소재별 성과" 표를 CSV로 추출한 결과입니다.

- 문서명: 찐당근 6월 — 퍼포먼스 캠페인 리포트 (문서상 날짜 2026.07.06)
- 추출 시점 원본 HTML SHA-256: `3448a9aef4c2bbfb1ab207a3ff1f9b7b76dfa2e2bfe31e8c2d474d0a68e86614`

원본 페이지는 외부 스크립트/스타일/데이터 요청이 전혀 없는 **완전 자기완결형(self-contained) HTML**
입니다. 표는 인라인 `<script>` 안의 데이터 배열(`D`)을 `ren()` 함수가 `<table>` 로 렌더링합니다.
따라서 로컬로 내려받은 HTML을 헤드리스 브라우저로 렌더링한 결과는 라이브 사이트와 동일합니다.

행 정렬 순서는 사이트 기본 표시 순서와 동일합니다(후기작성 CPA 오름차순, 전환없음 행은 마지막).

## 열(Column) 구성 — 10개

렌더링된 표의 2단 헤더를 그대로 평탄화한 것입니다. 두 탭 모두 열 구성이 같습니다.

1. `매체`
2. `소재`
3. `지출(만원)`
4. `CTR`
5. `후기작성 전환 수`
6. `후기작성 CPA(원)`
7. `후기작성 평가` — 고효율 / 보통 / 비효율 / 전환없음
8. `단골맺기 전환 수`
9. `단골맺기 CPA(원)`
10. `단골맺기 평가`

### 값 표기 규칙(원본 그대로)
- 숫자는 천 단위 콤마 포함(예: `1,817`, `191,286원`). **콤마가 포함된 값은 CSV에서 큰따옴표로
  인용**되어 열이 절대 밀리지 않습니다.
- 값이 없는 CPA/CTR은 원본과 동일하게 `—` (em dash)로 표기.
- 전환 수가 0인 경우 `0`.
- 평가 배지 텍스트는 원본 렌더링 텍스트 그대로.
- 한글이 엑셀에서 깨지지 않도록 파일에 UTF-8 BOM을 포함했습니다.

## 검증(Verification)

`verify.js` 로 다음을 자동 검증했으며 **전 항목 통과(✅ ALL CHECKS PASSED)** 했습니다.

- 행 수 일치: 후기작성 111, 단골맺기 35 (렌더링된 DOM 행 수 == 원본 데이터 배열 길이).
- **행/열 무결성**: 렌더링된 모든 행이 원본 데이터에서 계산한 값과 정확히 일치(누락·중복·혼선 0건).
- CSV 재파싱(RFC-4180): 모든 데이터 행이 **정확히 10개 필드**로 파싱됨(콤마로 인한 열 분리 없음),
  파싱 결과가 추출 행과 완전히 일치.
- 키워드 행 독립 검증: `review100` 5행, `당근제작_단골맺기` 5행이 원본 숫자로부터 손으로 계산한
  기대값과 정확히 일치.
